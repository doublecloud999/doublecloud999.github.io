Java 包装类型与自动装箱拆箱

四类八种包装类的对应关系、引用类型与值类型的差异、自动装箱与自动拆箱的底层实现(缓存机制与 valueOf),以及空指针、对象比较、性能开销三大重难点。

一、包装类型是什么#

  1. 是 Java 中的一组类,用于将基本数据类型封装成对象,因此与基本数据类型一样,也是四类八种
  2. Java 中的基本数据类型包括四类八种:char / byte / short / int / long / float / double / boolean。这些不是对象,但有的时候要将它们作为对象处理(比如集合存储基本数据类型、调用对象方法等等),包装类就可以用来处理基本数据类型的对象操作

1.1 常见包装类型,四类八种#

类别包装类型
整数类型Integer / Long / Byte / Short
浮点数类型Double / Float
布尔类型Boolean
字符型Character

包装类对象是引用类型,可以指向 null;基本数据类型是值类型,不能指向 null。

原因

  • 基本数据类型(值类型)的变量直接存储具体的数值
  • 引用数据类型(引用类型)的变量存储的是对象在内存中的地址(引用),null 就是引用类型专用的特殊值,表示它不指向任何对象

二、自动装箱#

自动将基本数据类型转换为相应的包装类型对象的过程。不是简单的赋值操作。

Integer num = 42;

自动装箱代码在编译之后会被替换为调用包装类的 .valueOf() 方法,比如这个就是 Integer.valueOf(42);。

对于有缓存的包装类而言:

  • valueOf() 方法首先判断这个值是不是在缓存范围中
    • 如果在,直接返回缓存中已经创建的这个包装类对象
    • 如果不在,会直接调用 new 包装类名(...) 方法创建一个新的包装类对象

对于没有缓存的包装类而言:

  • Float 和 Double 包装类的 valueOf() 方法底层就直接是 new 对象
  • Boolean 的 valueOf() 永远不会 new,只会返回 TRUE 或者 FALSE 静态常量

注意

  • 缓存是提前在堆里创建好的包装类对象
  • 不同包装类的缓存初始都是固定的范围,这个范围因类而异
  • 在没有通过外部手段修改(Integer 缓存可调整 JVM 参数)的情况下,缓存范围在程序运行期间是不变的(事实上除了 Integer 以外的包装类型都不能改变缓存)
  • 不是所有包装类都有缓存,也不是所有包装类的缓存都能被手动修改

三、自动拆箱#

自动将包装类型对象转换为相应的基本数据类型。

Integer num = 42;  // 自动装箱
int value = num;   // 自动拆箱

拆箱不是单纯的取值,也会出错。拆箱这行代码在编译之后底层调用 对象名.基本类型Value() 方法,比如这里调用的就是 num.intValue()。

由于包装类型是引用类型,它可以指向 null 值,所以自动拆箱可能出错:

  • 当你对一个指向 null 的包装类型拆箱,那么就是要将它转为基本数据类型,此时调用 对象名.基本数据类型Value() 方法(比如 intValue()) 就会出错,会直接抛出 NullPointerException。因为 null 是空,这个对象并不存储任何内存地址,自然也没有数据能适用于 基本数据类型Value() 方法

拆箱不涉及缓存复用,缓存只影响装箱阶段。拆箱调用方法之后会直接返回对象内部保存的基本数值,压根不用查询缓存,也不会复用缓存对象。

四、包装类型的方法和属性#

是每个包装类内部提供的用于操作、转换、比较其封装值的方法,以及表示取值范围、位数等信息的静态常量。

五、重难点#

1. 空指针异常

包装类变量指向 null 时,对它进行自动拆箱,因为 null 没有对象可以调用方法,所以会在运行时抛出 NullPointerException。

2. 对象比较

== 与 equals() 方法:

  • 对于基本数据类型,== 比较的是值是否相等
  • 对于引用数据类型,== 比较的是内存地址是否相同
  • equals() 是 Object 类的方法,包装类重写了它,用来比较两个包装类对象封装的数值是否相等

3. 性能开销

包装类的性能开销是指用包装类替代基本数据类型的时候,在内存占用和运行速度上产生的额外成本,主要来自对象创建、对象头、堆内存分配、自动装箱与自动拆箱的方法调用,以及可能增加的垃圾回收压力。
