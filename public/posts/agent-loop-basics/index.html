一、AgentLoop（智能体循环）#

思考阶段内部拆成两块:

  • 规划 Planning（把目标拆成子任务）
  • 工具选择 Tool Selection（选哪个工具、传什么参数）

围绕一个 Agent 循环,要回答三个问题:

问题内容
你给他看什么?上下文、历史、工具结果、记忆
他能碰什么?工具集和参数
什么时候停?finish 条件、最大轮次、超时、预算

1.1 workflow 和 Agent 的区别#

  • 前者步骤由人写死,成本可预测,只在预设路径内
  • 后者步骤由 LLM 运行时决定

二、PEAS 和环境四特性#

2.1 PEAS#

  • P:性能度量
  • E:环境
  • A:执行器
  • S:传感器

2.2 环境特性#

  • 部分可观察:一次查询拿不到全部信息,要记忆已经查过什么 + 换参数再查
  • 随机性:同样调用两次结果不同,需要重试、超时、幂等;结果要缓存
  • 多智能体:需要并发控制
  • 序贯且动态:当前动作影响未来,环境随时改变

三、三种推理范式#

3.1 ReAct#

推理和行动交替,每一步观测再修正。

思考、行动、观察,三步循环,每一步可以改变方向。

3.2 Plan and Solve#

先一次性出完整计划,再按步执行。

一次性生成步骤表,每一步都带有前序结果,目标一致但是计划错了全错。

3.3 Reflection#

产出后自我批判再迭代。

执行产出初稿,评审给反馈、按照反馈改稿,用成本换质量,延迟翻倍。

3.4 三种范式结构对比#

四、采样参数和 token#

4.1 采样参数（每天都调的东西）#

  • Temperature:调概率分布的陡峭程度,越小越保守
  • Top-k:只在概率最高的 K 个候选中采
  • Top-p:按累积概率动态截断
  • 优先级自上而下。如果温度设为 0,后面俩全失效了;后面俩 Top 二选一,一般选交集

4.2 token:决定成本和上下文#

  • 上下文成本按 token 计算,不是按照字数
  • API 按照 token 计算
  • 分词异常会让模型变怪

五、幻觉#

5.1 三种类型#

  • 事实性:与现实不符
  • 忠实性:摘要、翻译不忠于原文
  • 内在:和输入直接矛盾

5.2 三个成因#

  1. 训练数据本身有错
  2. 自回归机制本身是在挑最像的下一个词,没有事实核查模块
  3. 多步推理中的逻辑出错

5.3 三招#

  1. RAG 检索增强
  2. 上下文工程 + Memory
  3. 工具调用 + 多步验证

5.4 两个工程手段#

  • 结构化输出用 schema 校验（不合法就重试）
  • 关键结论要求引用来源（RAG 里把引用一起返回,让人能查）

六、Decoder-Only 和自注意力#

6.1 为什么是 Decoder-Only#

GPT 认为语言的核心任务就是预测下一个词,所以扔掉编码器,只留解码器。

6.2 自注意力#

  • 每个词生成 Q（问什么）、K（能被问什么）、V（我携带什么内容）
  • 用 Q 和所有词的 K 点积算相关性
  • softmax 归一化成权重,再对 V 加权求和

6.3 多头#

多头就是切 h 份各算一遍再拼,让 h 个「专家」分别关注指代、时态、从属等不同关系。

6.4 位置编码#

注意力本身不含顺序信息,"agent learns" 和 "learns agent" 对它完全等价,所以必须额外加位置编码。
