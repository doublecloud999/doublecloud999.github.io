字符串常量池

Java 细节拾遗:super、静态绑定与字符串常量池

本篇是「基础语法」的补充笔记,记录容易忘、需要反复看的细节。 一、super 与 static 的那些细节 1. private 方法不是「被隐藏」,而是「不可见、不可继承」 父类的 private 静态方法,子类压根就不能访问,自然也根本不能用 super 调用,编译直接报错。 2. 正确的「隐藏」概念 父类的静态方法如果没被 private 修饰,子类可以定义一个同名同参数的静态方法,这叫隐藏。隐藏后: 用父类名调用 → 执行父类的静态方法 用子类名调用 → 执行子类的静态方法 用 super 在实例方法中调用父类静态方法可以,但不推荐 3. super.静态方法() 的字节码行为 它在字节码中不会通过 this 去查找对象,而是直接解析到父类的静态方法。它和「父类名.静态方法()」在字节码层面几乎等价,都是静态解析,在编译阶段就会指定谁来继承。 4. 对象名引用调用 vs 父类名解析 调用方式 绑定时机 说明 对象名引用调用 动态绑定(多态) 运行时根据实际对象类型去找方法 父类名解析 静态绑定 编译阶段就确定调用哪个类的静态方法 5. super 不是一个对象,不能将 super 赋值给变量。 6. super 和 this 都不能在静态方法中使用。 7. 实例方法与静态方法在字节码层面的区别 实例方法调用时,局部变量表第 0 个槽位是 this。JVM 会偷偷把当前对象名作为第一个参数传入,方法内部用 this 接收这个参数 静态方法调用时,局部变量表没有 this,所以 JVM 不会传递对象名做参数 二、构造方法与 super() 8. 子类构造函数中不必须显式调用 super()(指手动写) ...
