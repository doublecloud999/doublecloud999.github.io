StringBuilder

Java 字符串三兄弟:String、StringBuilder 与 StringBuffer

一、String 是不可变的字符序列,用来表示字符串常量。 因为不可变,保证了线程安全、哈希值缓存、字符串常量池复用。 String 类被 final 修饰,不提供修改方法,用 byte[] 加编码标记。 字符串拼接在循环中会产生大量临时对象;String 是常量,修改会创建新对象。 面试题:String s = new String("abc") 创建几个对象(1 或 2 个) 如果字符串常量池中已经有 "abc",就只在堆中创建一个 String 对象 如果字符串常量池中没有 "abc",就需要先在字符串常量池创建一个 "abc",然后再去堆中创建一个 "abc" 另:String 是不可变的,任何看起来修改 String 的操作实际上都是创建了新的 String 对象。这是为了线程安全、支持字符串常量池共享、缓存哈希值。 二、StringBuilder 2.1 为什么需要它 平时输出用 System.out.println();每一次 println,系统都需要去调用系统底层的 I/O 接口,这个动作极其缓慢。 而 StringBuilder 能够减少 I/O 调用次数,属于 java.lang 包,不需要 import,直接就可以用。 2.2 机制 内部维护了一个可扩容的 byte[] 数组。 当你调用 sb.append() 时,它仅仅是在 JVM 的堆内存中修改这个底层数组的元素,并更新内部的 count(长度)变量 这个过程完全是用户态的内存操作,不涉及任何操作系统的 I/O 系统调用,其时间复杂度为摊销后的 O(1)。而且它不会像不可变的 String 那样每次拼接都创建新对象,从而避免了频繁触发垃圾回收(GC) 2.3 特性 可变的字符序列,线程不安全,多线程环境下需要加锁,扩容有性能开销,需要预设容量;但是性能高 用于频繁的字符串拼接操作,避免产生大量临时 String 对象 内部维护的是可扩容的字符数组,默认容量 16,扩容时新容量为旧容量 × 2 + 2 ...
