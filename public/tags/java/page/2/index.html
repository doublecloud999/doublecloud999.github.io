Java 异常处理

一、RuntimeException(运行时异常) 结论:RuntimeException 是未检查异常,编译时不需要强制处理 为什么:通常由程序逻辑错误引起,如空指针、数组越界,应在编码阶段避免 底层原理:继承自 Exception,但 JVM 不强制要求捕获。编译器在字节码生成时不检查 RuntimeException 的捕获 边界条件:可以捕获,但通常不建议捕获,应修复代码。如 NullPointerException、IndexOutOfBoundsException 二、CheckedException(检查时异常) 结论:CheckedException 是检查时异常,编译时强制要求处理 为什么:通常由外部环境引起,如文件不存在、网络中断,程序无法完全控制 底层原理:继承自 Exception 但不继承 RuntimeException 的类。编译器在编译时检查方法签名中的 throws 子句或 try-catch 块 边界条件:必须使用 try-catch 捕获或使用 throws 声明抛出;如 IOException、SQLException。不处理会直接编译报错 三、两者的对比 RuntimeException CheckedException 是否强制处理 否,编译时不需要 是,编译时强制 典型成因 程序逻辑错误(空指针、数组越界) 外部环境问题(文件不存在、网络中断) 常见例子 NullPointerException、IndexOutOfBoundsException IOException、SQLException 建议做法 通常不建议捕获,应修复代码 必须捕获或声明抛出 四、核心语法 throws、throw、try...catch、try...finally、try...catch...finally 结论:这是 Java 异常处理的核心语法 为什么:throws 用于声明方法可能抛出的异常;throw 用于手动抛出异常对象;try...catch 用于捕获并处理异常;try...finally 用于确保资源释放;try...catch...finally 结合两者 底层原理:throw 在字节码中对应 athrow 指令。try...catch 通过异常表(Exception Table)实现,指定字节码范围、异常类型和处理代码偏移量。finally 通过复制代码或 jsr / ret 指令实现 边界条件:throw 后不能有代码;throws 可以声明多个异常;try 块必须至少有一个 catch 或 finally;try...finally 没有 catch 时异常会向上抛出,但 finally 仍执行

Java IO 与文件流

一、什么是流 流是 Java 中用于输入输出的基本机制。IO 是 Input / Output(输入输出)的缩写。 1.1 流的分类 按方向 输入流:数据从其他地方读到内存 输出流:从内存写到其他地方 按单位 字节流:处理二进制数据,如图像、音频。字符流能处理的,字节流都能处理。以 Stream 结尾的通常是字节流 字符流:处理字符数据,用于文本文件(字节流能处理的,字符流不一定能处理)。以 Reader、Writer 结尾的一般是字符流 按功能 节点流:具有读写数据的功能,位于 IO 体系最底层,直接与特定的数据源(如磁盘文件 / 网络 Socket / 内存数组)建立连接,执行最原始的读写操作 过滤流:对节点流进行封装并增强功能(数据缓存 / 对象转换)。不能与数据源建立连接,只能包在节点流外部,对节点流的功能做增强 1.2 字节节点流 操作单元:byte[] FileInputStream:一次从流中读取多个字节,read 方法返回实际读到的字节数,读到文件尾部时返回 -1 FileOutputStream:一次写多个字节 1.3 字节过滤流 操作单元:byte[],但提供了 readInt()、writeObject() 等高级数据类型的封装方法。 缓冲流 BufferedInputStream:一次读多个字节,read() 返回读到的字节数,读到文件尾部时返回 -1。加入了缓冲区功能以提高 IO 效率,减少访问磁盘的次数 BufferedOutputStream:一次写多个字节,加入缓冲区以提高 IO 效率,减少访问磁盘的次数 对象流 ObjectInputStream:一次读多个字节,增加了将数据直接转换成八种数据类型和对象的功能 ObjectOutputStream:一次写多个字节,增加了将数据直接转为八种数据类型和对象的功能 1.4 字符节点流 FileReader:能一次从流中读取多个字符,返回读到的字符数,读到文件尾部时返回 -1 FileWriter:能一次写多个字符 1.5 字符过滤流 字符缓冲流 BufferedWriter:能一次写多个字符,支持输出换行符,能一次写一行;增加缓冲区功能以减少 IO 次数 BufferedReader:能一次读取多个字符,增加缓冲区功能,支持识别行结束符 \n、\r、\r\n,能一次读一行,减少 IO 次数 注意:BufferedReader 返回的字符串中不包含换行符。 ...

Java 基础笔记

一、前置知识 1.1 Java 的平台无关性(跨平台性) 一次编译即可在不同的操作系统中运行。 Java 程序被编译为字节码(.class 文件)而不是二进制机器码,不同的操作系统下载不同版本的 JVM(Java 虚拟机),再由对应版本的 JVM 将字节码解释为不同的机器码。 安装不同版本的 JVM,只需要下载对应版本的 JDK 即可。 1.2 垃圾回收机制(Garbage Collection) Java 的自动内存管理机制:垃圾回收机制可以自动分配和释放内存,程序员无需手动管理。 1.3 Java 的加载与执行 .java 文件是源码,其中定义了多个 class 类,有几个类就会生成几个 .class(字节码)文件。 生成 .class 文件后,即使把 .java 文件删除也不影响执行,但这样就没法再修改源码了。 javac —— 编译命令 javac 专门负责编译,会检查 .java 文件中的代码是否合法:合法则生成字节码文件,不合法则报错。 javac 后面跟的是 .java 文件的路径,可以是绝对路径也可以是相对路径。比如一个 .java 文件中定义了一个叫 a 的类,那么 javac 就会生成 a.class,这是字节码文件,操作系统无法直接运行。 java —— 运行命令 java 命令用来运行 Java 程序,后面跟的是类名(比如 java a)。执行 java a 之后: 启动 JVM(Java 虚拟机); 虚拟机内启动类加载器(classloader); 类加载器通过环境变量 classpath 去硬盘上找那个叫 a.class 的文件; JVM 找到该字节码文件中的 main 方法,并将该方法解释成机器码; 操作系统通过执行机器码与底层硬件交互。 小结 ...
