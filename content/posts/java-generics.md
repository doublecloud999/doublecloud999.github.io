## 一、泛型类

你再创建一个类的时候，在类名后面写 `<T>`，T 是声明出来的一个类型变量。

- T 在没有上界的时候可以是任意类型；但如果是 `class MyBox<T extends Number>` 就只能传入 `Number` 及其子类，传其他的类直接编译报错
- 创建一个新对象的时候要指定 T 是什么(不是赋值，而是交给 T 一个引用类型名)，比如 `String` 或者 `Integer`，但是前提是只能是引用类型，不能是基本类型

**结论:** 类型参数声明在类名之后，整个类体中都可以使用它。让容器类承载任意类型而不丢失类型安全。

**作用:** 把类型检查从运行期提前到编译器，同时消除强制类型转换。

## 三、泛型擦除

泛型是给**编译器**看的，不是给 JVM 看的。

Java 泛型通过**类型擦除**实现，泛型代码在编译成 `.class` 字节码文件之后，泛型基本消失，JVM 运行的时候不知道泛型的存在。

编译器在编译期间动态地将泛型 T 擦除成 `Object`；如果你写的是 `T extends B`，B 是你已经定义好了的类，那么编译器就会把 T 替换成 B。

类型擦除让泛型代码能够与引入泛型之前的 Java 类库和二进制代码保持兼容，编译器会通过必要的**类型转换**和**桥方法**保持类型安全和多态语义。

### 3.1 泛型的好处

- 在编译期间进行类型检测
- 使用 `Object` 类型需要手动添加强制类型转换，降低代码可读性
- 泛型可以自己限定类型

### 3.2 泛型的限制

由泛型擦除机制导致的，**凡是需要在运行时明确知道具体类型的操作，泛型都不允许你做**。

1. 可以声明 T 类型的变量，但是你**不能直接 `new T()`** 实例化类型参数
2. **泛型参数绝对不能是基本类型**，只能用基本类型对应的引用类型替代
3. `static` 上下文不能引用这个类声明的类型参数
4. **泛型数组绝对不能实例化**，你只能 `new Object[]`

### 3.3 一个典型的编译报错

```java
public void print(List<String> list) { }
public void print(List<Integer> list) { }
```

报错，因为**类型擦除**之后 JVM 眼中你的代码是:

```java
public void print(List list) { } // 参数类型是 List
public void print(List list) { } // 参数类型也是 List
```

相当于是第二行重写了第一行，但是重写要求参数列表一定不同，就不成立，直接报错。

## 四、BridgeMethod 桥方法

BridgeMethod 由**编译器自动生成**，用来在继承泛型类时保持多态。

## 五、通配符

泛型类型是固定的，不太灵活，通配符允许类型参数的变化，用来解决**泛型无法协变**的问题。
