## 一、super 与 static 的那些细节

**1. `private` 方法不是「被隐藏」,而是「不可见、不可继承」**

父类的 `private` 静态方法,子类压根就不能访问,自然也根本不能用 `super` 调用,编译直接报错。

**2. 正确的「隐藏」概念**

父类的静态方法如果没被 `private` 修饰,子类可以定义一个同名同参数的静态方法,这叫**隐藏**。隐藏后:

- 用父类名调用 → 执行父类的静态方法
- 用子类名调用 → 执行子类的静态方法
- 用 `super` 在实例方法中调用父类静态方法可以,但不推荐

**3. `super.静态方法()` 的字节码行为**

它在字节码中不会通过 `this` 去查找对象,而是直接解析到父类的静态方法。它和「父类名.静态方法()」在字节码层面几乎等价,都是静态解析,在编译阶段就会指定谁来继承。

**4. 对象名引用调用 vs 父类名解析**

| 调用方式 | 绑定时机 | 说明 |
|----------|----------|------|
| 对象名引用调用 | 动态绑定(多态) | 运行时根据实际对象类型去找方法 |
| 父类名解析 | 静态绑定 | 编译阶段就确定调用哪个类的静态方法 |

**5. `super` 不是一个对象**,不能将 `super` 赋值给变量。

**6. `super` 和 `this` 都不能在静态方法中使用。**

**7. 实例方法与静态方法在字节码层面的区别**

- 实例方法调用时,局部变量表第 0 个槽位是 `this`。JVM 会偷偷把当前对象名作为第一个参数传入,方法内部用 `this` 接收这个参数
- 静态方法调用时,局部变量表没有 `this`,所以 JVM 不会传递对象名做参数

## 二、构造方法与 super()

**8. 子类构造函数中不必须显式调用 `super()`(指手动写)**

- 如果父类**没有**无参构造函数(指构建父类时,没有手动设置父类无参构造函数,只手动设置了有参构造函数,这样系统不会自动生成无参构造函数),子类**必须**显式调用 `super(参数)`
- 如果父类**有**无参构造函数,子类可以不用显式调用 `super()`

**9. 编译器自动插入 `super()` 的规则**

一个子类的构造方法中,如果你没有在第一行手动添加 `this()`(这是个构造方法,有参或者无参都可以),编译器就会自动在这里插入 `super()`(这是父类的构造方法,有参或者无参都可以)。

如果子类某个构造方法写了 `this()` 调用构造方法,那么编译器就不会再自动插入 `super`,而是由 `this` 调用的那个构造方法,以 `super` 形式调用父类构造方法。

> **结论:父类构造方法一定会被调用,而且只执行一次。**

## 三、字符串与常量池

**10. `new` 与字符串变量的创建过程**

`new` 一定会在堆内存中开辟空间创建一个对象。

字符串变量创建时:先去字符串常量池中检查是否存在——不存在则先在字符串常量池中创建,再去堆中创建;存在则直接去堆中创建。

**11. 字符串常量池**

字符串常量池是堆中一块专门用来存储字符串字面量的特殊区域(JDK 7+)。堆是 JVM 内存中最大的一块,用来存储所有对象实例。常量池的作用是避免重复创建相同内容的字符串,节省内存。

**12.** 由于 `String` 是不可变的,可以安全地被多个变量共享。

**13. `==` 与 `equals()`**

- `==` 比较的是内存地址
- `equals()` 比较的是地址里存的值

## 四、访问权限与接口 default

**14. 访问权限**

- `default`(包级私有):包内所有类都可以访问
- `protected`:包内所有类 + 不同包的子类

**15. 接口方法的 `default` 是什么意思?**

JDK 8 允许在接口中定义被 `default` 修饰的方法。这种方法**必须要有方法体 `{}`**,实现类可以不重写这个方法,直接继承接口的默认实现。

在字节码中,接口中的 `default` 方法带有 `ACC_PUBLIC` 和 `ACC_DEFAULT` 标记。

> 注:JVM 规范中并没有 `ACC_DEFAULT`,是通过 `ACC_PUBLIC` 且非 `ACC_ABSTRACT` 来标识的。

**16. `protected` 的边界**

`protected` 修饰的字段或者方法,只能在同包当中或者本类当中,或者不同包内的本类的子类的类体当中,而且**不能出子类体的大括号**。

## 五、接口与继承的补充细节

**17. 接口的三条默认规则**

- 方法默认 `public abstract`,只有声明没有实现
- 字段默认 `public static final` 常量
- 不能有构造器,不能保存实例状态,不能直接实例化

![接口的定义](/images/java/interface-definition.png)

**18. 实现接口的规则**

一个**非抽象类**实现接口的时候必须将接口中所有方法加以实现;一个类可以**实现多个接口**,但是只能继承一个抽象类。

继承和实现都存在的话,`extends` 在前,`implements` 在后。

**19. 绝对不能 `new Collection`**

![不能直接 new Collection](/images/java/interface-no-new-collection.png)

**20. `Object` 是所有类的父类**

Java 里任何一个类,不管你有没有写 `extends`,都直接或间接继承 `Object`。所以 `Object` 类型的引用变量可以指向任何对象,这是**集合能存任何东西**的原因。

**21. 向上转型与向下转型**

无论是向上转型还是向下转型,两种类型之间都必须有继承关系:

- 编译,看的是**声明类型**
- 运行,看的是**实际创建的对象类型**
- 向上转型(子类转父类)是**自动**的、安全的
- 向下转型(父类转子类)是**强制**的、有风险的

声明父类引用、创建子类对象,这是向上转型,绝对安全、自动转换,但是只能调用**父类有的方法**(堆内存里真有一个子类对象)。

声明子类引用、创建父类对象,这是向下转型,你不加强转编译器报错,加了强转运行报错。

但如果是向下转型的时候两边都是接口,你不加强转编译不报错,运行的时候会报错。解决方法:转型前先用 `if (m instanceof K)` 判断一下,只有返回 `true` 再去强转,就能避免崩溃。

## 六、其他容易忘的点

**22. 局部变量没有初始值,成员变量才有**

**成员变量(类属性)**你不给它赋值,系统会给你兜底,自动给个**默认值**;**局部变量(方法里的变量)**你不给它赋值,编译器直接报错,根本不让你用。

![局部变量与成员变量的默认值](/images/java/local-var-default.png)

**23. `@Override` 的规则**

子类 `@Override` 父类方法,名字和参数列表必须与父类**一模一样**;返回值类型必须与父类的返回值类型相同或者是父类返回值类型的**子类**,访问权限不能比父类更严格。

**24. `final` 必须手动赋值**,两种方式:

- 直接赋值
- 在构造方法外面定义,在构造方法里面赋值

总而言之,必须在**构造方法结束之前**赋值,一旦构造方法结束(对象创建成功)这个值就不能再改变了。如果你不给它赋值,JVM 在分配对象内存时,其实底层依然会先赋**默认值**(0),只是编译器不允许你读取到那个默认值。

**25. `System.out.println(对象)` 会调用 `toString()`**

如果这个类重写了 `toString()` 方法那就按照重写的来;如果没重写,那就按照 **Object 类**原本的默认方法来做,对象名@哈希值。

**26. 怎样查看 enum 字节码?**

去 **IntelliJ** 的 Out 里面找字节码文件,复制路径,直接去文件管理器里打开路径,用终端打开文件,`javap -c 文件名`。
